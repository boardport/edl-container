Готовый к использованию Docker-контейнер для утилиты [EDL (Qualcomm Emergency Download Tool)](https://github.com/bkerler/edl) от B. Kerler.

Текущий репозиторий входит в экосистему **[BoardPort](https://github.com/boardport)** и предоставляет изолированную среду
со всеми предустановленными драйверами, библиотеками и загрузчиками для комфортной работы через простые Make-команды.

> 🤖 **Инструкция для AI-ассистентов:** Если вы являетесь автономным AI-агентом или LLM-помощником, перед выполнением любых задач
> обязательно ознакомьтесь с проектным регламентом в [AGENTS_RU.md](./AGENTS_RU.md).

## 🎯 О проекте и экосистеме BoardPort

Главная цель инициативы **BoardPort** — портирование современных дистрибутивов Linux, свежих версий ядер, легковесных ОС
и специализированных прошивок на широкий спектр неподдерживаемых, "забытых" или устаревающих устройств:

- 📶 **Китайские 4G/LTE USB-модемы и роутеры** (донглы/«свистки» на базе Qualcomm MSM8916, MSM8909, MSM8937 — семейство OpenStick, UFI и аналоги).
- 📱 **Смартфоны и планшеты** прошлых поколений на платформах Qualcomm Snapdragon.
- 🧩 **Отладочные платы (dev boards)** и одноплатники промышленного или хобби-сегмента (DragonBoard 410c, Inforce и др.).
- 📟 **IoT-модули и телематика**, требующие низкоуровневого восстановления, снятия дампов или перехода на чистый Linux.

В рамках этой экосистемы **EDL Container** обеспечивает надёжный, воспроизводимый канал взаимодействия
с устройствами через сервисный режим аварийной загрузки **Qualcomm 9008 (EDL)** без засорения хост-системы зависимостями.

## ⚡ Порядок работы (Quick Start Workflow)

Низкоуровневая работа с чипсетами Qualcomm в сервисном режиме состоит из четырёх простых шагов:

### Шаг 1. Подготовка хоста (права доступа к USB)

Для прямого взаимодействия контейнера с USB-шиной настройте udev-правило. Создайте файл `/etc/udev/rules.d/51-edl.rules`:

```udev
# Qualcomm Snapdragon EDL Mode (9008)
SUBSYSTEM=="usb", ATTR{idVendor}=="05c6", ATTR{idProduct}=="9008", MODE="0666", GROUP="plugdev"
```

Примените изменения:

```bash
sudo udevadm control --reload-rules
sudo udevadm trigger
```

> ⚠️ **Конфликт с драйвером ядра `qcserial`:** Если ядро Linux автоматически подхватило устройство как последовательный порт
> (`/dev/ttyUSB*`), освободите интерфейс для `libusb`:
>
> ```bash
> sudo rmmod qcserial
> ```

---

### Шаг 2. Перевод устройства в режим EDL и подключение к ПК

Переведите плату, модем или телефон в режим Qualcomm Emergency Download (9008) и подключите к USB-порту компьютера:

- **Программно (если устройство работает):**
  - Из запущенного Android: `make edl-reboot-adb` (отправляет `adb reboot edl`).
  - Из режима Bootloader / Fastboot: `make edl-reboot-fastboot`.
- **USB-модемы и донглы (MSM8916 / MSM8909):**
  - Зажмите аппаратную кнопку на плате (при наличии) и вставьте модем в USB-порт.
  - Либо замкните контрольные точки (EDL Test Points) пинцетом в момент подачи питания.
- **Смартфоны и планшеты:**
  - Зажмите комбинацию аппаратных клавиш (обычно `Громкость+` и `Громкость-`) и подключите USB-кабель к выключенному устройству.
  - Либо используйте специальный кабель с кнопкой (EDL / Deep Flash Cable).

---

### Шаг 3. Проверка подключения

Убедитесь, что устройство определилось на шине USB с идентификатором `05c6:9008`:

```bash
lsusb | grep 05c6:9008
```

Проверьте связь с устройством и чтение таблицы разделов:

```bash
make edl-printgpt
```

---

### Шаг 4. Выполнение операций

Запустите чтение, сохранение полного бэкапа или прошивку нужного раздела через готовые команды `make edl-*`.

## 🛠️ Основные команды (Make-автоматизация)

Все рутинные параметры `docker run`, проброс шины USB и сохранение прав на создаваемые файлы уже автоматизированы.

### 🔍 Диагностика и инспекция

```bash
# Вывод таблицы разделов (GPT)
make edl-printgpt

# Сведения об аппаратном накопителе (eMMC / UFS, размеры секторов и блоков)
make edl-storageinfo

# Универсальный вызов любой команды bkerler/edl (или показ встроенной справки)
make edl
make edl secureboot
```

### 💾 Резервное копирование и чтение

```bash
# Полный бэкап всех разделов устройства в папку dumps/
make edl-rl

# Снятие дампа одного раздела (например, boot в dumps/boot.img)
make edl-r boot dumps/boot.img

# Посекторный бинарный образ всей физической памяти (Raw Flash Dump)
make edl-rf dumps/full_flash.bin
```

### ⚡ Прошивка и стирание разделов

```bash
# Запись подготовленного образа в выбранный раздел
make edl-w boot dumps/boot_new.img

# Стирание (очистка) раздела (например, userdata)
make edl-erase userdata
```

### 🔄 Управление питанием и перезагрузка

```bash
# Перезагрузка устройства в штатный рабочий режим
make edl-reset

# Горячая перезагрузка обратно в режим EDL (Warm reset)
make edl-reset-edl
```

### 💻 Интерактивная среда и кастомные загрузчики

```bash
# Вход в интерактивную оболочку контейнера (с adb, fastboot и утилитами)
make edl-sh

# Использование внешнего Firehose-загрузчика (если автоопределение не сработало)
make edl-printgpt --loader=loaders/prog_emmc_firehose_8916.mbn
```

## 🐳 Запуск через Docker CLI (без Make)

Если в вашей системе отсутствует GNU Make, либо контейнер запускается в CI/CD-пайплайне,
вы можете вызывать образ напрямую через стандартный Docker CLI:

```bash
docker run --rm -it \
  --privileged \
  --net=host \
  -v /dev/bus/usb:/dev/bus/usb \
  -v "$(pwd)/dumps:/opt/edl/dumps" \
  -e EDL_DUMP_UID=$(id -u) \
  ghcr.io/boardport/edl printgpt
```

Подробное описание параметров запуска, переменных окружения (`EDL_DUMP_UID`, `EDL_DUMP_GID`),
точек монтирования и рецептов использования доступно в **[docker/README_RU.md](./docker/README_RU.md)**.
