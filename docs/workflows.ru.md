# Сценарии работы и решение проблем

Практическое руководство по выполнению типовых операций с чипсетами Qualcomm в сервисном режиме (9008):
чтение и сохранение резервных копий, прошивка образов, работа с Firehose-загрузчиками,
восстановление поврежденных устройств и диагностика неисправностей.

---

## 1. Диагностика и инспекция памяти

Перед чтением или модификацией разделов убедитесь в стабильности связи с чипсетом:

```bash
# Чтение таблицы разделов (GPT)
make edl-printgpt

# Сведения об аппаратной геометрии памяти (eMMC / UFS / NAND)
make edl-storageinfo

# Проверка статуса Secure Boot и состояния криптографических ключей
make edl secureboot
```

Если чипсет корректно возвращает разметку GPT, значит стек Sahara и Firehose полностью инициализирован.

---

## 2. Резервное копирование (Backups)

Все создаваемые дампы автоматически сохраняются в локальный каталог `dumps/` в корне проекта.

### 2.1. Дамп одного раздела

Для сохранения конкретного раздела (ядра, вторичного загрузчика, модемной прошивки) укажите имя раздела и целевой файл:

```bash
# Сохранение раздела boot в файл dumps/boot.img
make edl-r boot dumps/boot.img

# Сохранение вторичного загрузчика aboot
make edl-r aboot dumps/aboot.img
```

### 2.2. Полный бэкап всех разделов устройства

Перед экспериментами по адаптации ядер и загрузчиков рекомендуется снять полный бэкап всех существующих разделов:

```bash
make edl-rl
```

Команда парсит GPT и последовательно выгружает каждый раздел в каталог `dumps/` под оригинальным именем метки.

### 2.3. Посекторный бинарный образ всей физической памяти (Raw Flash)

Для создания полного посекторного дампа накопителя (включая MBR/GPT, скрытые служебные дорожки и пользовательские данные):

```bash
make edl-rf dumps/full_flash.bin
```

---

## 3. Прошивка и стирание разделов

> **Предупреждение:** Запись некорректного образа в разделы первичных загрузчиков (`sbl1`, `xbl`, `tz`, `rpm`, `aboot`)
> нарушает загрузочную цепочку. Всегда сохраняйте резервную копию раздела перед его перезаписью!

### 3.1. Запись образа в раздел

```bash
# Прошивка модифицированного ядра в раздел boot
make edl-w boot dumps/boot_new.img

# Прошивка корневой файловой системы
make edl-w rootfs dumps/rootfs_custom.img
```

### 3.2. Стирание (очистка) раздела

Используется для сброса пользовательских данных, очистки поврежденных кэшей или подготовки памяти под новую разметку:

```bash
# Очистка раздела userdata
make edl-erase userdata

# Очистка раздела кэша
make edl-erase cache
```

## 4. Работа с Firehose-загрузчиками

Утилита содержит встроенную базу программаторов (`Loaders/`), которые подбираются
автоматически на основе аппаратных идентификаторов чипсета (HWID, PK Hash).

### Использование внешнего / кастомного программатора

Если для вашей платы автоопределение не сработало (например, редкая ревизия чипсета или уникальный вендорский ключ):

1. Поместите бинарный файл программатора (например, `prog_emmc_firehose_8916.mbn`) в рабочую директорию.
2. Передайте параметр `--loader` через переменную `MAKEARGS`:

```bash
make edl-printgpt MAKEARGS="--loader=loaders/prog_emmc_firehose_8916.mbn"
```

Либо запустите дамп раздела с указанием программатора:

```bash
make edl-r boot dumps/boot.img MAKEARGS="--loader=loaders/prog_emmc_firehose_8916.mbn"
```

## 5. Управление питанием и перезагрузка

После выполнения операций устройство можно перезагрузить напрямую через USB-команду:

```bash
# Перезагрузка устройства в штатный рабочий режим
make edl-reset

# Горячая перезагрузка обратно в режим EDL (Warm Reset)
make edl-reset-edl
```

Горячая перезагрузка удобна при отладке, когда необходимо сбросить состояние чипсета без физического отключения кабеля питания.

## 6. Восстановление («Раскирпичивание») и Troubleshooting

### Зависание на этапе Sahara («Hello packet failed / Timeout»)

- **Причина 1: Захват порта драйвером `qcserial`.**
  Проверьте `dmesg | grep ttyUSB`. Если ядро зарегистрировало последовательный порт, выгрузите модуль: `sudo rmmod qcserial`.
- **Причина 2: Чипсет находится в промежуточном зависшем состоянии.**
  Выполните команду `make edl-reset-edl`. Если чипсет не реагирует, полностью обесточьте устройство на 5 секунд.
- **Причина 3: Недостаточное питание по шине USB.**
  Подключайте устройство напрямую к USB-портам на задней панели материнской платы, избегая пассивных разветвителей.

### Ошибка цифровой подписи (Secure Boot / Sahara Command NACK)

- **Причина:** На чипсете активирован аппаратный Secure Boot (прожжены eFuses), а используемый Firehose-программатор
  не подписан соответствующим OEM-ключом производителя.
- **Решение:** Найдите официальный сервисный программатор (MBN/ELF) из заводской сервисной прошивки именно вашей модели
  и передайте его через флаг `--loader=...`.

### Ошибка «Permission denied» при доступе к файлам дампов на хосте

- **Причина:** Контейнер запускался напрямую без сопоставления UID, и файлы созданы суперпользователем `root`.
- **Решение:** Make-команды автоматически передают `-e EDL_DUMP_UID=$(id -u)`.
  Если файлы уже созданы с правами root, восстановите права на хосте:
  `sudo chown -R $USER:$USER dumps/`.
